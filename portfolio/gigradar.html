GigRadar is a personal, local-first London live-music discovery and urgency intelligence engine. It continuously monitors 100+ grassroots music venues across London boroughs, tracking event lifecycles from announcement to sell-out, scoring ticket urgency, and extracting structured gig data directly from unstructured social flyers using local multimodal vision models.

Unlike commercial aggregator platforms (DICE, Ticketmaster, Songkick) that optimize for ad placement and ticket resale markups, GigRadar extracts a zero-day signal directly from venue websites, promoter feeds, and physical flyers—giving gig-goers actionable notice before competitive ticket drops sell out.

Observation & Ingestion

Raw observation events are ingested via custom venue adapters, RSS feeds, and visual poster uploads. Ingested payloads are persisted as immutable RawObservation records, preserving raw DOM snapshots, timestamps, and parser versions for auditing.

Semantic Deduplication

Incoming observations are matched against canonical records using a two-tier strategy: exact deterministic keys (venue ID + date + artist slug) with a semantic cosine distance fallback via pgvector. Borderline matches (0.10–0.30 distance) are routed to a human review queue.

Lifecycle & Edge Separation

State changes generate timestamped entries in EventChangeLog, driving real-time urgency scoring heuristics (e.g. available → low_tickets). The public demo runs as a secure, isolated SvelteKit client on Cloudflare Pages using deterministic sample data.

Architectural Decisions

Engineering Decisions & Trade-Offs

Data Ingestion

Custom Scraping vs Official Ticketing APIs

Decision

Build custom, direct DOM scrapers and ICS feed readers for London grassroots venues rather than relying on DICE, Ticketmaster, or Songkick APIs.

Why

Official ticketing APIs reflect events only after they are officially listed, meaning tickets are discovered at the same time as the wider market. Scraping venue event calendars and Instagram flyers directly yields a zero-day signal—discovering shows days before competitive ticket releases.

Alternatives Considered

Commercial event aggregator APIs (DICE, Ticketmaster Discovery, Resident Advisor GraphQL).

Trade-offs & Rationale

Requires maintaining resilient DOM parsing abstractions that gracefully handle markup changes. We mitigate fragility by isolating parsers behind a unified BaseAdapter contract with deterministic fallback fixtures.

Database & Vectors

PostgreSQL + pgvector vs Dedicated Vector Databases

Decision

Use a single PostgreSQL instance with the pgvector extension for both ACID relational event storage and high-dimensional semantic vector search.

Why

Keeping relational metadata (venue geometry, ticket pricing, change history) and 768-dimensional embeddings in the same database guarantees transactional ACID consistency in a single operational boundary, completely eliminating the distributed dual-write synchronization bugs common with standalone vector DBs.

Alternatives Considered

Pinecone, Qdrant, Milvus, or PostgreSQL full-text search (tsvector).

Trade-offs & Rationale

While standalone vector databases scale higher for multi-million vector datasets, GigRadar processes tens of thousands of London events annually—well within the sub-millisecond index threshold of PostgreSQL's HNSW vector indexing.

AI Strategy

Local Ollama Multi-Model AI vs Cloud APIs

Decision

Execute all production intelligence locally using Ollama (qwen3-vl for flyer OCR and nomic-embed-text for vector embeddings) following the philosophy: "Use the strongest AI to build the product; use the smallest AI to run the product."

Why

Cloud AI APIs introduce recurring subscription costs, vendor lock-in, latency variance, and external rate limits. Running local models gives a 100% private, cost-free sandbox that parses hundreds of heavy flyer images offline with zero billing anxiety.

Alternatives Considered

OpenAI GPT-4o-mini vision API, Anthropic Claude 3.5 Sonnet, Google Gemini 1.5 Flash.

Trade-offs & Rationale

Local vision inference requires 2–3 seconds on CPU/local GPU vs sub-second cloud calls. Since flyer ingestion is an asynchronous background batch process, throughput and zero cost far outweigh sub-second response times.

Backend Architecture

FastAPI with Pydantic v2 Contract Boundaries

Decision

Standardize backend services on FastAPI with Pydantic v2 schemas for strict boundary validation and native asynchronous concurrency.

Why

High-frequency concurrent polling across 100+ venue endpoints requires an async-native runtime (ASGI). Pydantic v2's Rust core delivers ultra-fast schema serialization and guarantees strict type enforcement when parsing semi-structured JSON outputs from local AI extractors.

Alternatives Considered

Django REST Framework (synchronous, heavy batteries), Flask (lacks native async and type validation).

Trade-offs & Rationale

Lacks Django's built-in admin panel and ORM migrations, requiring explicit SQLAlchemy and Alembic configuration. This trade-off was intentionally made for granular control over async database sessions.

Deployment & Edge

Cloudflare Pages Separation & HMAC-SHA256 Auth

Decision

Deploy the frontend showcase as an edge SvelteKit application on Cloudflare Pages, isolated from the stateful database, using Web Crypto API HMAC-SHA256 signed session tokens.

Why

Eliminates serverless cold starts, provides global edge distribution (<50ms response), and prevents surprise cloud infrastructure bills. The deterministic sample dataset ensures 100% demo reliability without exposing internal database credentials.

Alternatives Considered

Vercel, AWS Amplify, static export with hardcoded string cookie auth.

Trade-offs & Rationale

Requires isolating write paths and using mock fixtures for the public demo. Web Crypto HMAC verification provides edge-native security with constant-time signature comparison without requiring Node.js runtime bindings.

Engineering Lessons

Upfront Architecture & Single Source of Truth

Decision

Establish strict repository modularity (apps/, services/, packages/, docs/) with Architectural Decision Records (ADRs) recorded on every major design pivot.

Why

Iterative prototyping without explicit architectural boundaries leads to environment drift and refactoring friction. Planning schemas, domain models, and hosting strategies upfront reduces wasted code churn and ensures full traceability.

Alternatives Considered

Ad-hoc unstructured prototyping.

Trade-offs & Rationale

Adds slight upfront documentation overhead, but drastically accelerates implementation speed, agentic pair programming, and code review consistency.

Engineering Rigor

Development Process & Tooling

🐍 Python Tooling Authority (`uv`)

We enforce a strict single-toolchain boundary: uv is the sole authority for Python 3.12+ virtual environment creation (.venv), lockfile resolution, and script execution. This eliminates interpreter shadowing, pip version drift, and slow dependency resolution.

uv sync --all-extras
uv run pytest tests/ -v

⚡ Deterministic Task Runner (`Justfile`)

All developer workflows are standardized behind declarative Justfile recipes. This provides instant command discovery across polyglot stacks (Python + Node) and prevents brittle shell aliases or Makefile tab syntax issues.

just dev — Start backend & edge frontend
just review-fast — Run all lint & type gates

🔒 Rootless Containers (`Podman Compose`)

Local infrastructure services (PostgreSQL 16, pgvector, Ollama model runner) are orchestrated using Podman Compose in rootless mode, ensuring complete local isolation without requiring privileged Docker root daemon sockets.

just up — Launch PostgreSQL + pgvector container
just down — Cleanly teardown background services

🛡️ Strict Quality Gates & Type Safety

Zero-tolerance CI quality gates combining Pyright strict static type checking, Ruff linting/formatting, SvelteKit check for template safety, and Gitleaks for pre-commit credential leak prevention.

uv run ruff check . && uv run pyright
npm --prefix apps/demo run check

🧪 Testing & In-Memory Verification

Comprehensive unit and integration test suite using pytest with in-memory SQLite fixtures for urgency heuristic scoring, adapter payload parsing, and pgvector cosine distance deduplication routing.

pytest tests/test_urgency.py
pytest tests/test_deduplication.py

🚀 Automated Preview Smoke Tests

CI pipeline executes an automated Node.js smoke testing harness against live Cloudflare Pages preview builds, validating 18 critical assertions across public routes, HMAC auth redirects, guest mode, logout, and self-hosted fonts.
